2. RULES AND GOTCHAS THAT APPLY EVERYWHERE
===============================================================================

BLINDED ASIMOV ONLY: rabbit_fit.py -t -1. Never fit 5 TeV data (-t 0) while the
uncertainty model is being built. Luca's fitterSCETlibNP.py DEFAULTS TO -t 0,
so always pass -f '-t -1' to it.

TRADITIONAL IMPACTS ONLY: --doImpacts, and NOT --globalImpacts /
--impactType global. With the SCETlib-NP param model the lambda parameters float
unconstrained, so their GLOBAL impact is 0 by construction and the whole
nonperturbative uncertainty is reclassified into `stat` (measured: resumNonpert
global 0.000 vs traditional 2.81). Global impacts are not a cross-check, they
are wrong here. Passing --impactType global to the plot scripts also dies with
KeyError: 'global_impacts_grouped' unless the fit ran with --globalImpacts.

UNITS: --scaleImpacts 2.0 (plots) / --scale 2.0 (rabbit_print_impacts.py)
converts fit units to alpha_s x 10^-3.

SLURM MEMORY = CPUs: the submit cluster has MaxMemPerCPU=2048 MB, so a memory
request silently also requests CPUs: --mem=300G -> 150 CPUs, --mem=480G -> 240
CPUs. Only submit80 (1.5 TB, 384 cpus) and submit81-1 (500 GB, 384 cpus) can
host >= ~150 CPUs, so big jobs wait for those two. Ask for the smallest size
that works, and request -c equal to the implied CPU count so they get used.
  Check: scontrol show job <id> | grep NumCPUs ; squeue --start -u hayden17
  If submit81-1 shows State=...DRAIN, it needs an admin to resume it; until then
  everything big queues behind submit80.

MaxRSS IS UNRELIABLE: sacct polls, so it misses short peaks (a 300G OOM reported
MaxRSS 287 GB, below a run of the same job that SUCCEEDED at 309 GB). For an
OOM-killed job it just reports the cgroup ceiling. Do not size from it alone.

MISSING INPUTS ONLY WARN: the histmakers print a WARNING and carry on when a
theory-correction or ByHelicity file is missing, then the downstream
setupRabbit step fails (or worse, silently lacks a systematic). After any
production, compare the histogram list against a reference output.

PLOTS:
  * Use savehists_jul30/plot_com.py <com> <rabbit_plot_hists args>, not
    rabbit_plot_hists.py directly: it has no --com flag, so every 5 TeV plot comes
    out stamped "(13 TeV)".
  * The x-range flag is --axlim (two values PER AXIS). --xlim is accepted and
    silently ignored.
  * Keep one gallery per date and separate energies with -p/--postfix (Luca asked
    for this): -o ~/public_html/<date> -p alphas_5tev
  * Gallery: https://submit.mit.edu/~hayden17/<tag>/
  * A wrong --varNames entry is a silent no-op; list the names first (see 7b).

DUPLICATE SCRIPTS: extend an existing script with a CLI flag rather than copying
it for a small change.

-------------------------------------------------------------------------------
STEP 1. HISTMAKER: scripts/histmakers/mz_dilepton.py
-------------------------------------------------------------------------------
What it does: reads every event of data and MC, applies the Z->mumu selection
and all corrections/weights, and fills boost histograms: the nominal fit
histogram (yll x ptll) plus one variation histogram per systematic.

Command (step1_histmaker/run.sh; Luca's exact flags):
  TC=scetlib_dyturbo_LatticeNPLambda4Bugfix_FranksVals_CT18Z_N3p0LL_N2LO
  python scripts/histmakers/mz_dilepton.py --axes yll ptll --csVarsHist \
    -o /work/submit/hayden17/13tev_oct3/step1_histmaker --maxFiles -1 -j 150 \
    --theoryCorr $TC ${TC}_pdfas ${TC}_pdfvars \
      scetlib_dyturbo_LatticeNP_MSHT20mbrange_N3p0LL_N2LO_pdfvars \
      scetlib_dyturbo_LatticeNP_MSHT20mcrange_N3p0LL_N2LO_pdfvars \
    --pdfs ct18z msht20mcrange_renorm msht20mbrange_renorm \
    --unfolding --poiAsNoi --unfoldingAxes ptVGen absYVGen helicitySig --unfoldingInclusive \
    --quarkMassCorr MiNNLO_Zbb

Flags:
  --axes yll ptll          the reco fit observable (2D). Default is mll ptll.
  --csVarsHist             also book Collins-Soper angle histograms (not fitted)
  --maxFiles -1            all files (use a small number only for quick tests)
  -j 150                   threads; match the SLURM -c
  --theoryCorr A B ...     reweight MiNNLO to these predictions. The FIRST is the
                           nominal: SCETlib N3+0LL resummation matched to DYTurbo
                           NNLO, CT18Z PDF, lattice NP model ("FranksVals" central
                           NP values, lambda4 bug fixed). _pdfas gives the alpha_s
                           +-0.002 templates (0.116/0.120) -> the pdfAlphaS POI;
                           _pdfvars the CT18Z eigenvectors; MSHT20mb/mcrange the b
                           and c quark mass variations
  --pdfs ct18z msht20...   which LHE PDF weight sets to book (CT18Z central/errors;
                           MSHT20 mb/mc range sets renormalized to their own central)
  --unfolding --poiAsNoi   book gen-level histograms (ptVGen x absYVGen x helicity)
  --unfoldingAxes ...      next to the reco ones; the SCETlib-NP response matrix
  --unfoldingInclusive     (reco x gen) is built from these. Inclusive = no
                           fiducial cut, mass window only
  --quarkMassCorr MiNNLO_Zbb  extra b-quark mass correction as a theory variation

Inputs it reads:
  Events      /scratch/submit/cms/wmass/NanoAOD/ (default for *.mit.edu hosts,
              wremnants/utilities/data_paths.py). 2016 post-VFP:
                data     SingleMuon
                signal   DYJetsToMuMu MiNNLO (+ PDFExt), DYJetsToMuMu M-10to50
                bkgs     DYJetsToTauTau, TTTo2L2Nu/SemiLeptonic, single top (s, t, tW),
                         WW/WZ/ZZ, W(+/-)->munu and ->taunu MiNNLO,
                         GGToLL / GGToMuMu (photon induced), QGToDYQTo2L, QGToWQToLNu
  Theory      wremnants-data/data/TheoryCorrections/
                ${TC}_CorrZ, ${TC}_pdfas_CorrZ, ${TC}_pdfvars_CorrZ .pkl.lz4
                scetlib_dyturbo_LatticeNP_MSHT20m{b,c}range_N3p0LL_N2LO_pdfvars_CorrZ.pkl.lz4
                MiNNLO_Zbb_CorrZ.pkl.lz4
              .../TheoryCorrections/ByHelicity/{AlphaS,PDFsFromCorrs}/
                w_z_gen_dists_${TC}_{pdfas,pdfvars}_Corr_maxFiles_m1_skimmed.hdf5
                (alpha_s / PDF variations split by angular coefficient -> the
                 *_CorrByHelicity histograms setupRabbit needs)
  Muon effs   wremnants-data/data/muonSF/allSmooth_GtoHout_vtxAgnIso.root (+ _altBkg),
              smoothSF3D_uTm30to100_vtxAgnIso.pkl.lz4: smoothed tag-and-probe SFs
              for reco, tracking, idip (2D) and trigger, iso (3D in eta, pt, uT)
  Calibration wremnants-data/data/calibration/ (momentum scale/resolution + variations)
  plus pileup/vertex weights, prefiring, CVH bad-module SF (--cvhBadModules sf).

Selection (build_graph): MET filters, electron veto, corrected muons,
HLT_IsoMu24 || HLT_IsoTkMu24, veto muons (exactly 2), good muons (pt in (26, 65), |eta|<2.4,
medium ID, |dxybs|<0.05, isolation < 0.15), opposite charge, Z mass window,
standalone-muon cuts, trigger matching, then all weights.

Resources: run on SLURM with -c 150 --mem=300G (job.sbatch). MaxRSS ~300 GiB.
  It OOMs on the login node (~78 GB free) and at 110G on SLURM, both while
  BUILDING THE GRAPH for Zmumu (the unfolding + helicity histograms), i.e. before
  any event is read -- a 1-file test needs the same memory as the full run.
  Runtime 3h40-4h10 at 150 threads (~2.5e5-1.4e6 evt/s; slows near the end where
  the big signal-MC files are).
Output: step1_histmaker/mz_dilepton_${TC}_Corr_maxFiles_m1.hdf5 (7.5 GB);
  per sample: Zmumu 721 histograms, Ztautau 586, Wmunu 114, data 11.
CHECK: no "does not exist" warnings in the log, and the histogram list matches
  the reference (only harmless renames: hNValidPixelHits*, hparmgrads*).

-------------------------------------------------------------------------------
STEP 2. DATACARD: scripts/rabbit/setupRabbit.py
-------------------------------------------------------------------------------
What it does: turns the histograms into the rabbit input tensor ("card"):
picks the fit observable, groups processes, converts every systematic histogram
into a nuisance parameter (lnN/shape, symmetrized, grouped), stores data and
the SCETlib-NP response matrix.

Command (step2_card/step2.sh):
  python scripts/rabbit/setupRabbit.py -i <step-1 output> \
    --fitvar ptll-yll -o /work/submit/hayden17/13tev_oct3/step2_card/ \
    --noi alphaS --npUnc none --axlim ptll 0j 44j --postfix realdata --realData \
    --excludeNuisances '^.*scetlibNP.*$' --storeResponseMatrix

Flags:
  --fitvar ptll-yll        fit ptll x yll (39 x 20 = 780 bins)
  --axlim ptll 0j 44j      keep ptll < 44 GeV ("j" = axis VALUE; plain = bin index)
  --noi alphaS             alpha_s (pdfAlphaS) is the parameter of interest
  --npUnc none             no fixed nonperturbative variations...
  --excludeNuisances '^.*scetlibNP.*$'   ...and drop any that remain: the NP
                           uncertainty comes from the param model's free lambdas
                           at fit time instead (double counting otherwise)
  --storeResponseMatrix    embed R (reco x gen) and N_gen as the 'scetlib_np'
                           auxiliary, which the param model reads
  --realData               store the observed data in the card (ignored by -t -1)
  --postfix realdata       output directory name suffix
Processes: Zmumu (signal), Ztautau, PhotonInduced, Other.
Output: step2_card/ZMassDilepton_ptll_yll_realdata/ZMassDilepton.hdf5
CHECK: 3746 nuisances, 4 processes. Compare to Luca's card with
  /work/submit/hayden17/eff_oct2/insitu_smoke/cmp_tensors.py <card A> <card B>
  ("hsystgroupidxs" differing only in ORDER is Python set order, not a change).

-------------------------------------------------------------------------------
STEP 3. FIT: rabbit_fit.py in TWO stages
-------------------------------------------------------------------------------
Why two stages: computing the Hessian naively through the SCETlib-NP param model
differentiates the bT fold once per parameter (~3750 of them) and would need
~33 TB. So stage A minimizes WITHOUT the Hessian, and stage B computes it at the
stage-A minimum with a straight-through surrogate (hessian_straightthrough=1)
that only exposes the <= 8 lambdas to autodiff; hessian_gn=1 (Gauss-Newton,
drops the second-derivative term) is exact for Asimov. Details in the
param_model.py docstring and docs/HESSIAN_PLAN.md.

Submit both (stage B waits for A): scripts/submit_fit.sh <card> <fitdir>

STAGE A (scripts/fit_stageA.sh) -- Luca's command with -t 0 -> -t -1:
  rabbit_fit.py <card> -v 4 \
    --paramModel wremnants.postprocessing.scetlib_np.SCETlibNPParamModel \
      np_model_nu_fit=tanh_6 np_model_fit=tanh_6 xparam_default=lambda6_nu=0.01,lambda6=0.01 \
    --freezeParameters lambda_inf lambda_inf_nu lambda6 lambda6_nu \
    -r wremnants.postprocessing.scetlib_np.np_damping_wall.NPDampingWall \
       wremnants.postprocessing.scetlib_np.np_damping_wall.NPDampingMapping smallb=1 margin=0 \
    --regularizationStrength 5.0 --minimizerMaxiter 1000 \
    -t -1 --noHessian -o <fitdir>
STAGE B (scripts/fit_stageB.sh):
  same --paramModel tokens + hessian_straightthrough=1 hessian_gn=1, same
  --freezeParameters / -r / --regularizationStrength, then
    --externalPostfit <fitdir>/fitresults.hdf5 --noFit --minimizerMaxiter 1000 \
    -t -1 --doImpacts -o <fitdir>/cov_trad

Flags:
  --paramModel SCETlibNPParamModel   the nonperturbative TMD parameters (lambdas)
                           become free fit parameters; the signal yield is
                           recomputed from them on the fly through the response
                           matrix stored in the card
  np_model_(nu_)fit=tanh_6 functional form of the NP model in the fit
  xparam_default=...       starting values for lambda6(_nu)
  --freezeParameters ...   lambda_inf(_nu), lambda6(_nu) fixed; the rest float
  -r NPDampingWall NPDampingMapping smallb=1 margin=0
                           regularization: a one-sided penalty that keeps the NP
                           function DAMPING (coefficients >= margin). margin=0 =
                           plain positivity (code default 5e-3 is stricter);
                           smallb=1 also enforces the small-b walls
  --regularizationStrength 5.0   penalty x exp(2*tau); 5.0 is Luca's value for
                           this fit (his workflow default is 3.0). At the Asimov
                           point the wall is inactive, so tau does not change
                           Asimov results; it matters for data fits
  -t -1                    Asimov: data = model expectation at nominal
  --noHessian (A) / --externalPostfit + --noFit (B)   the two-stage split
  --doImpacts              traditional impacts (see section 2)
  NOT used, deliberately: Luca's stage B also had -m Project ch0 ptll
  --computeVariations --computeHistErrors --computeHistImpacts --saveHists
  --saveHistsPerProcess. These only feed template plots and OOM through the param
  model (see 7b for how to make plots).

Resources: A 128G/64 cpu, ~10-14 min, peak ~40 GB. B 480G/240 cpu, ~10-15 min,
  used 424 GiB -> 480G is REQUIRED; queue for submit80/81 can be ~1 day.
CHECK: the log prints "NPDampingWall: margin=0 smallb=1" (confirms the wall
  config reached the regularizer) and "edmval" ~1e-27. A "reco agreement"
  warning about ~20 bins in the top ptll bin is the known qT>100 grid truncation.
  At Asimov, pdfAlphaS and all nuisances post-fit = 0.
Read results:
  rabbit_print_impacts.py <fitdir>/cov_trad/fitresults.hdf5 -s --impactType traditional --scale 2.0

PROBLEMS HIT AND HOW THEY WERE SOLVED
-------------------------------------------------------------------------------
1. Missing theory inputs. These exist ONLY in Luca's local wremnants-data
   (/home/submit/lavezzo/alphaS/WRemnants/wremnants-data), not upstream, and were
   copied (byte-identical, uncommitted) into ours:
     TheoryCorrections/${TC}_CorrZ, ${TC}_pdfas_CorrZ, ${TC}_pdfvars_CorrZ .pkl.lz4
     TheoryCorrections/ByHelicity/AlphaS/w_z_gen_dists_${TC}_pdfas_Corr_maxFiles_m1_skimmed.hdf5
     TheoryCorrections/ByHelicity/PDFsFromCorrs/w_z_gen_dists_${TC}_pdfvars_Corr_maxFiles_m1_skimmed.hdf5
   The ByHelicity ones were missed at first: the histmaker only WARNED, ran 3.7 h,
   and setupRabbit then failed ("Did not find systematic ..._pdfas_CorrByHelicity").
   Harmless warnings that Luca's run has too: renesanceEW_CorrZ and the *_CorrW
   files (W corrections, W is a tiny background here), PDF weights for dibosons.
2. rabbit API change (code fix in
   wremnants/postprocessing/scetlib_np/np_damping_wall.py, UNCOMMITTED as of Oct 5).
   The PR #709 merge moved rabbit to 9a84645, which (a) passes indata= to every
   regularizer, (b) hands the -r key=value tokens (smallb=1 margin=0) to the
   REGULARIZER instead of the mapping, (c) calls set_expectations(..., parms=).
   NPDampingWall crashed on each in turn. Just swallowing the new arguments would
   have silently fallen back to margin=5e-3; the fix routes smallb/margin through
   and prints them. Penalty scaling (exp(2 tau)) is unchanged between versions.
3. Memory: see step 1 and step 3 resources.
4. Selection difference vs Luca: PR #709 (commit 3dac3e2f) changed the
   z_dilepton default --pt from [34, 26, 60] (upstream main, Luca) to
   [49, 26, 65] (to match its in-situ Chebyshev window 26-65 GeV). Our card has
   +2.7% events, identically in data and MC, growing with ptll (x1.00 below
   10 GeV, x1.06 at 26-28, x1.3-1.5 above 30). For Luca's selection exactly, add
   --pt 34 26 60 to the histmaker. Effect on sigma(alpha_s): none on the total.

7d. b,c quark masses
-------------------------------------------------------------------------------
 1. Source: NanoAOD branch LHEPdfWeightAltSet12 (MSHT20nnlo menu, 88 entries: 65
    central + 7 alpha_s + 9 mcrange @72 + 7 mbrange @81). LHAPDF sets
    MSHT20nnlo_mbrange_nf5 / _mcrange_nf5; theory_utils.py msht20mbrange_renorm /
    msht20mcrange_renorm.
 2. What they are: dedicated MSHT20 releases with m_b (m_c) changed and the PDF
    refitted -- not PDF-error eigenvectors. Hence a separate bcQuarkMass group.
 3. Renormalization (renorm: True): every member divided by its range set's own
    central, so it isolates the mass effect instead of importing the
    CT18Z<->MSHT20 difference. Matches the 13 TeV from-MiNNLO scheme.
 4. Then clip_tensor(res, theory_weight_truncate), x nominal_weight -> filled into
    ptll_pdfMSHT20mbrange / ...mcrange (ptll x yll x pdfVar).
 5. Reduction (setupRabbit_5TeV.py): only the extreme members, per the 13 TeV
    BC_QUARK_MASS_VARIATIONS convention: mbrange pdf1/pdf6, mcrange pdf1/pdf8.
 6. symmetrize="quadratic" -> SymAvg + SymDiff per pair: 16 raw members -> 4
    nuisances, group bcQuarkMass (in theory).
 7. No 90% -> 68% CL conversion: the range sets are not 90% CL eigenvectors.
 8. Applied as a multiplicative reweight of the MiNNLO weight on top of the
    CT18Z-corrected nominal -- NOT through SCETlib+DYTurbo (unlike pdfAlphaS/pdfCT18Z).

7g. Why the fit stays 2D (angular variables)
-------------------------------------------------------------------------------
Adding cos(theta*)/phi* to the fit observable looked like an alpha_s gain, but it
is acceptance-convolution structure, not physics:
 1. The 13 TeV alpha_s fit does not use the angles by default (mz_dilepton.py
    --axes; --csVarsHist only books them for angular-coefficient studies).
 2. Where 13 TeV does fit angle-sensitive observables (the W mass, muon pt/eta/
    charge), it carries the full detector model with uncertainties: hundreds of
    efficiency nuisances in muon pt/eta, momentum-scale and resolution
    systematics, prefiring, and helicity-decomposed theory (angular-coefficient
    QCD-scale nuisances). The fit can only use angular structure as far as data
    constrain that model.
 3. At 5 TeV without those systematics the same construction becomes an
    unprotected assumption. So: fit ptll x yll until the efficiency and
    momentum-scale uncertainties are in, then revisit; --factorizeSystAxes is the
    lighter-weight A/B switch. Helicity smoothing becomes useful only if the fit
    moves to the finer 4D angular observables (half-MC test Jul 13: not needed in 2D).

Replaced by the in-situ method (section 6). Kept because the code is still in the
branch, the measurements are reusable (e.g. reco for open question 4), and the
yll finding below is still an open physics question.

lowPU ('1HLT') parity throughout: per-muon maps, step names matching 13 TeV so
the styles.py nuisance groups work, and the trigger combined with lowPU's own
formula.

HISTMAKER FLAGS: two SEPARATE corrections, pass both --
  --muonScaleFactors        <sf_id.hdf5>           the ID       (reco x idip)
  --muonTriggerScaleFactors <sf_trig_permuon.hdf5> the trigger  ('1HLT')
Both are per muon. The ID weight is SF_reco(mu1)*SF_idip(mu1)*SF_reco(mu2)*
SF_idip(mu2); the trigger one is lowPU's combination
  (1 - prod(1-eps_data)) / (1 - prod(1-eps_MC)) = P(>=1 muon fired) data/MC,
which is why its map stores eps_data and eps_MC separately rather than a ratio.
DO NOT CONFUSE with --muonEventScaleFactors: the SAME trigger correction in
event-level form, so it replaces --muonTriggerScaleFactors rather than adding to
it (mz_5TeV.py raises if both are given). Parity wants the per-muon one.

THE THREE STEPS
  reco     probe = loose muon             pass = Muon_isGlobal
  idip     probe = loose muon + isGlobal  pass = Muon_mediumId
  trigger  per-muon eps for data and MC, combined as lowPU does:
             corr = (1 - prod(1-eps_data)) / (1 - prod(1-eps_MC))
  reco x idip = the analysis ID (mediumId && isGlobal). Split because reco carries
  the central eta dips and idip the endcap one; per muon the split is the chain
  rule. NO iso step (the old 5 TeV selection had no isolation cut). NO cvh step,
  and there cannot be one: the 5 TeV DATA NanoAOD has no CVH branches (scarekit
  calibration) and an SF is a ratio of two efficiencies.

THE CHAIN
1. MEASURE the per-muon ID (relaxes the muon ID to loose, so this run's physics
   hists are NOT the analysis ones -- always a separate run)
     python3 scripts/histmakers/mz_5TeV.py --muonEfficiencyHists \
       --muonCorr scarekit -j 16 -o <dir> --postfix effmeas
   Both muons of the Z are probes, no tag/probe split (David's method).
   --muonEffEtaBins defaults to 48 (0.1 wide): measure fine, the SF builder can
   only COARSEN.
2. ID SF MAP
     python3 scripts/analysisTools/make_muon_efficiency_sf_5TeV.py \
       -i <effmeas.hdf5> -o sf_id.hdf5 --rebinPt 5
   SF = eps_data/eps_MC per (eta, pt, charge, step), backgrounds subtracted bin by
   bin. Recommended 48 eta x 2 pt. The script REFUSES a map holding both the merged
   'id' step and reco+idip (the helper multiplies every step).
2b. ID MAP WITH THE effSystTnP ALTERNATIVE (one invocation, both measurements)
     python3 scripts/analysisTools/make_muon_efficiency_sf_5TeV.py --fromNanoAOD \
       --probeTrigger 'HLT_HIMu17 || HLT_HIL3DoubleMu0' \
       --altProbeTrigger 'HLT_HIL1DoubleMu0' --nEta 48 --nPt 2 -j 8 \
       -o sf_id_withalt.hdf5
   --fromNanoAOD counts the probes itself, so nominal and alternative share ONE
   code path and differ only by the probe trigger.
3. PER-MUON TRIGGER MAP
     python3 scripts/analysisTools/make_muon_trigger_sf_5TeV.py --fromNanoAOD \
       -o sf_trig_permuon.hdf5 --mergeCharge -j 8
   Use --fromNanoAOD: the in-histmaker booking (book_trigger_pair_hist) ABORTS ON
   DATA with "Incompatible underflow/overflow for histogram conversion" (narf atomic
   fill path; unresolved). --scanBinning first if changing the binning.
4. APPLY + TEMPLATE VARIATIONS
     python3 scripts/histmakers/mz_5TeV.py --muonScaleFactors sf_id.hdf5 \
       --muonTriggerScaleFactors sf_trig_permuon.hdf5  ... (normal prod args)
   -> nominal SF into nominal_weight for all MC
   -> ptll_effStatTnP_{reco,idip,trigger_DATA,trigger_MC}
   setupRabbit_5TeV.py picks these up with NO new flag, mirrors them (one-sided:
   SF -> SF+sigma), prunes negligible ones (--effPruneThreshold, default 1e-4 on
   the largest relative template change), and groups them as
   muon_eff_stat[_<step>] / muon_eff_syst[_<step>] / muon_eff_all / experiment.

HOW THE PER-MUON TRIGGER WAS EXTRACTED (no trigger objects)
TrigObj holds NO muon objects in this production (0 entries with id == 13 in
5.16M events; only id 11). Muon_triggerIdLoose is an offline quality flag, NOT a
record that the muon fired; the L1_* branches are event-level. So no muon can be
tagged. lowPU's combination formula read BACKWARDS extracts eps per muon from
whether the EVENT fired, as a function of both muons' bins:
    P(fires | muons in bins a, b) = 1 - (1 - eps_a)(1 - eps_b)
fitted by maximum likelihood over (bin1, bin2, pass) counts (analytic gradient,
exact Hessian). lowPU's formula: lowpu_efficiencies.hpp, applied in mz_lowPU.py;
ours: muon_efficiencies_5TeV.hpp (at_least_one), trigger_efficiency_fit_5TeV.py.
  Validation: toys give bias +9e-5 on flat truth; injected dips of 0.70 and 0.80
  come back 0.7063+-0.0355 and 0.7923+-0.0268; event rate reproduced to 2e-6.
  Real data (12 eta x 10 pt, charge-merged = 120 bins):
     data  86705 events,     925 double failures,  0/120 at a bound
     MC   3824376 events,    236 double failures, 13/120 at a bound
     eps_data mean 0.894, eps_MC ~0.99
  Information budget = the DOUBLE-failure count (rate ~ (1-eps)^2).
  The nuisances are EIGENVECTORS of the fit covariance, not per bin: a single event
  constrains a PRODUCT, so the overall (1-eps) scale is near-degenerate with the bin
  structure (|rho| up to 0.7; marginal pulls 0.46-0.84 wide). Eigenvectors are what
  the 13 TeV SMOOTH SFs use.

GOTCHAS FROM THIS WORK
  * NEVER book a step after its own cut (ID after the ID filter = 1 by
    construction; same for the trigger after HLT_HIMu17). The measurement relaxes
    the ID to loose and uses HLT_HIMu17 || HLT_HIL3DoubleMu0 (--muonEffProbeTrigger).
    Dropping the trigger filter entirely makes the job >12 h (job 6614264).
  * Measure fine, coarsen later.
  * Empty map cells (SF 1, variance 0) give variations identical to nominal = a FLAT
    direction in the likelihood. Pruned in setupRabbit.
  * Tensor axes must not share a name with a fit axis ("Hist instance cannot contain
    axes with duplicated names") -> effBinYll / effBinPtll.
  * The C++ helpers take (float, float); ptll/yll are DOUBLE and cppyy will not
    narrow them ("could not convert argument 1"). Define float copies first.
  * ROOT::VecOps::Map with a lambda and RVec<int>(RVec<bool>) do not compile in this
    build; use ROOT::VecOps::Where.
